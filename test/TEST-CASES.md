## TC-001：未登录用户发送聊天消息
- **前置条件**：不登录，直接打开 https://kazispace.ai/
- **操作步骤**：在聊天输入框输入 "Hello"，点击发送
- **预期结果**：
  - 方案A：提示用户需要先登录，然后跳转到登录页
  - 方案B：允许匿名聊天但限制次数，正常返回回复
- **实际结果**：❌ **FAIL** — 返回 HTTP 422 错误，页面显示 "HTTP 422"，无任何友好提示
- **严重程度**：Critical
- **根因**：前端未做认证拦截。未登录时直接发送聊天请求（无 token），后端返回 401/422。前端应拦截并引导登录。

## TC-002：OTP 登录流程
- **前置条件**：打开 https://kazispace.ai/login
- **操作步骤**：
  1. 输入手机号 +77015551234
  2. 点击"获取验证码"
  3. 输入收到的验证码
  4. 点击登录
- **预期结果**：登录成功，跳转到首页/chat，显示用户信息
- **实际结果**：❌ **FAIL** — 点击"Send Code"返回 HTTP 422，验证码未发送，无验证码输入框出现
- **根因**：前端 `api-client.ts` 发送 `{"contact": "+77015551234"}`，后端要求 `{"phone": "+77015551234"}`。字段名 `contact` vs `phone` 不一致，后端 Pydantic 校验失败返回 422
- **严重程度**：Critical
- **备注**：用正确字段 `phone` 通过 curl 调用可正常返回验证码（mock code `123456`），后续 verify → login → chat 全链路 API 均可正常工作。问题仅在前端字段名
